## 계획대로 유지한 처리

기존 MuQ-MuLan-large revision `2e01c796b71dca71b45251384c04cd7b237c9020`와 `angry music expressing rage and hostility` 문구를 그대로 사용했다. FP32·CUDA·기존 MuQEngine으로 전체 음원을 모노24kHz로 읽고 최대10초 균등 연속 구간으로 처리했다. 짧은 구간은 기존 방식으로 앞부분을 반복해10초로 채웠다. native 구간 유사도의 단순 평균을 저장했으며 확률·보정된 강도로 변환하지 않았다.

실제 엔진의 calc_similarity 반환값을 바꾸지 않고 복사해 구간별8점수를 보관했다. 체크포인트는 strict 로딩 및 모든 상태 텐서의 동일성 검사를 거쳤다. 기존 모델의8개 점수는 기록했지만 anger→Anger 이외의 상관·매핑은 탐색하지 않았다. 보류61개는 평가하지 않았다.

같은 원곡 발췌012/013,027/045/047,058/059는 각각 하나의 그룹으로 묶었다. 각 그룹에서 원래 Anger 평균과 모델 분노 점수를 각각 평균한 다음45쌍을 비교했다. 49발췌 보조 상관은 별도 진행 판단이나 우월성 주장에 사용하지 않았다.

## 실행 중 길이 검사 수정

첫 실행은2개 처리 후003번에서 중단됐다. 검증 코드가 수학적 올림을 예상했으나 기존 librosa는 소수점 계산 뒤 올림해6개 파일(003/058/059/068/087/091)에서1샘플 더 생성했다. 이는 약0.042ms 차이이며 모든49개에서 기존 처리 규칙을 별도로 확인했다. 원래 계획·실행·부분2개 점수·중단 기록은 v1에 보존했다. 모델의 음원 처리나 점수 계산은 바꾸지 않고 검사만 기존 처리와 일치시킨 v2에서49개 전체를 다시 실행했다. v1 부분 점수를 결과에 섞거나 유리한 실행을 선택하지 않았다. 사전 계획의 예상 길이 표현은 이 소수점 올림 규칙으로 명시적으로 보완했다.

## 검산과 제한

관련 검사5개가 통과했다. 평가 계획·실행 코드·모델·음원 해시를 확인했고,49개 파일을 다시 디코딩해 원PCM을 대조했다. 전체 구간의 누락 없음과8개 유한 점수·구간 평균을 검산했다. 결과 작성 시 원곡 그룹을 별도로 재구성하고 SciPy로 순위 상관과 고정 seed의5,000회 재표집 구간·진행 판정을 다시 계산해 일치를 확인했다. 모델 추론을 반복해 결과를 고른 것은 아니다.
