# 공개 장르 태그를 활용한 추가 학습의 실현 가능성

> 과거 실험 기록 · 공개본 2026-10-29. 본문의 모델·라벨·기본값·다음 단계는 작성 당시의 상태입니다. 현재 0.6.0 familiar 구성의 정확도를 뜻하지 않습니다. [현재 구성과 해석 범위](../README.md)를 먼저 확인하세요. 본문의 로컬 원시 자료·실험 도구는 이 공개본에 포함하지 않습니다.


2026-10-26 · 메타데이터 조사와 기술 동작 점검 · 실제 장르 학습 전

## 판단

**현재 환경에서 작은 장르 판별기를 학습하는 연구 경로는 기술적으로 가능하다.** 우선안은 기존 MuQ-MuLan의 음악 특징 추출을 고정하고, 그 특징을 입력받는 마지막 13출력 선형 판별기만 공개 태그로 학습하는 방식이다. 사용자가 음악을 듣고 정답을 직접 붙일 필요는 없다.

이번에 확인한 것은 데이터 분리 가능성과 기술 동작이다. 새 학습 음원을 받거나 실제 장르 태그로 판별기를 학습하지 않았으므로, 이전 문구 방식보다 정확해질지·J-pop에 잘 맞을지·하우스나 컨트리 혼동이 줄지는 아직 모른다. 현재 API 0.5.0의 10장르, 모델 가중치, 감정·분위기는 유지한다.

## 어떤 학습인가

공개 업로더 태그를 교사 신호로 쓰는 **약한 지도학습을 통한 전이학습**이다. 기존 MuQ-MuLan이 추출한 오디오 특징 위에 작은 판별기를 붙인다. 사용자 보상으로 모델을 훈련하는 강화학습·RLHF는 아니다. [공식 MTG-Jamendo 설명](https://github.com/MTG/mtg-jamendo-dataset)은 태그가 콘텐츠 업로더에게서 왔음을 밝히며, [MuQ 공식 사용법](https://github.com/tencent-ailab/MuQ)은 오디오 임베딩 추출을 제공한다.

| 접근 | 현재 확인과 선택 |
|---|---|
| 텍스트 문구 수정 | 이미 시험한 P1은 조건 미달로 종료. 반복해서 더 고르지 않음 |
| 고정 음악 특징 + 작은 선형 판별기 | **우선 연구안.** 실제 특징 추출과 역전파 동작 확인. 메타데이터 학습·검증 분할 가능 |
| 음악 모델 전체 미세조정 | 이번에 검증하지 않음. 처음부터 큰 모델의 전체 가중치를 학습하는 단계로 가지 않음 |
| 사용자 피드백 기반 강화학습 | 정확한 장르 보상과 전문가 판정이 없어 이번 목적의 우선안으로 삼지 않음 |

## 실제 기술 점검

기존 보관 음원 RWC_G016의 첫 10초를 사용해, 기존 검증 로더로 모델을 읽고 특징을 추출했다. 별도 학습·정확도 평가에 이 한 곡을 사용한 것은 아니다.

| 항목 | 실제 확인 |
|---|---|
| 환경 | Windows, RTX 4070 12GB, PyTorch 2.11.0+cu128 |
| 오디오 특징 | 유한 값의 `1 × 512` 벡터 |
| 판별기 | CPU의 `Linear(512, 13)` |
| 판별기 파라미터 | 가중치·편향 합계 **6,669개** |
| 역전파 | 합성 다중 라벨 목표로 BCE 손실과 판별기 기울기가 유한함을 확인 |
| 큰 모델 | `requires_grad=False`, 기울기 누적 0 |
| 파라미터 갱신 | 옵티마이저 실행 **0회**, 판별기 가중치 변경 없음 |
| CUDA 메모리 | 이 단일 점검에서 최대 할당 약 **2.68GiB** |

기술 점검의 합성 목표는 장르 정답이 아니다. 실제 장르 학습 성능이나 모델 전체 미세조정 가능성을 보여 주는 실험으로 해석하지 않는다. 대규모 음원 처리 속도·메모리도 이 한 측정으로 보장하지 않는다.

학습안은 전체 음원을 기존과 같은 최대 10초 구간으로 처리한 뒤, **원시 음악 임베딩의 평균**을 곡별 특징으로 저장하는 것이다. 선형 판별기의 평균 구간 로짓은 평균 임베딩의 로짓과 같으므로 곡별 특징을 CPU 학습에 재사용할 수 있다. sigmoid 점수의 평균과 같다는 뜻은 아니다. 음원 전체의 태그를 모든 구간의 확정 정답으로 간주해 구간을 독립 곡처럼 부풀리지 않는다.

350곡의 곡별 512차원 float32 특징 행렬은 계산상 약 0.72MB다. 이는 모델·오디오·중간 버퍼·전체 작업 메모리를 포함하지 않는다. 비용이 큰 부분은 작은 판별기의 역전파보다 음원 확보·검증과 음악 특징 추출일 가능성이 높다. 정확한 전체 처리시간은 아직 실측하지 않았다.

## 학습·검증 후보의 실제 규모

이미 보관한 공식 split-0 메타데이터의 고정 revision `cafd8e20c265ed84f1e61f1c875327971f43a62f`를 사용했다. 이전에 확보했던 아티스트 ID 270개와, 아직 오디오를 보지 않은 최종 후보 33개 아티스트를 제외했다. 60~600초 조건의 메타데이터에서 다음 후보를 선정할 수 있었다.

| 역할 | 공식 출처 | 선정 목표 | 후보 수 |
|---|---|---|---:|
| 학습 | train | 14개 원본 태그 그룹별 20곡 | **280곡** |
| 조정·모델 선택 | validation | 같은 그룹별 5곡 | **70곡** |
| 별도 최종 진단 | test | 이전에 고정한 경계 15곡 + 대조 18곡 | **33곡** |

14개 원본 선정 그룹은 house·techno·disco·folk·country·pop·rock·metal·jazz·classical·hiphop·reggae·blues·rnb/soul이다. House와 Techno를 별도 할당해 broad electronic 태그만 많은 곡을 고르는 일을 피한다. 출력은 두 그룹을 electronic으로 대응하는 기존 13개 공간이다.

모든 선정 후보는 한 곡당 한 아티스트 ID·앨범 ID를 사용한다. 학습 280·검증 70·별도 평가 33을 합친 383개 아티스트 ID가 전부 다르다. 공식 train/validation/test 간 곡·아티스트 ID 중복도 0을 확인했다. 실제 인물의 여러 ID·커버·근접 중복이나 모델 사전학습과의 중복을 제거했다는 뜻은 아니다.

| 경계 원본 태그 | 사용 가능한 학습 아티스트 | 사용 가능한 검증 아티스트 |
|---|---:|---:|
| house | 198 | 64 |
| techno | 196 | 67 |
| disco | 78 | 24 |
| folk | 202 | 65 |
| country | 61 | 34 |

이 숫자는 이번 제외·길이 조건을 적용한 메타데이터 후보 수이며, 음원이 실제로 다운로드된 수나 정답 품질의 보증이 아니다. 전체 코퍼스를 받을 계획도 아니다.

## 태그를 어떻게 학습할 것인가

복수로 등록된 장르를 모두 보존한다. House·Techno·electronic은 electronic, rnb·soul은 rnb_soul로 고정 대응하며, folk·country·disco 등은 합치지 않는다. 새 13개 출력 중 acoustic 속성·J-pop 정체성·세부 장르를 추가하지 않는다.

선정된 학습 후보 중 104곡, 검증 후보 중 30곡에는 대응 장르 태그가 여러 개 있다. 따라서 하나만 정답으로 강제하는 softmax 대신 **13개의 독립 로짓을 가진 다중 라벨 학습**을 우선안으로 둔다. 출력에서 여러 장르를 자동 확정할 임계값까지 검증된 것은 아니다. 현재 사용자 정책에 맞는 가장 가까운 첫 후보와 순위는 제공할 수 있지만, sigmoid를 정답 신뢰도로 표시하지 않는다.

누락 태그는 확정적인 음성이 아니다. 첫 연구 기준점으로 BCE 손실을 사용한다면 등록 태그는 양성, 미등록 태그는 **잡음이 있을 수 있는 약한 음성 학습 목표**라는 가정을 명시해야 한다. 공개 태그의 누락 문제를 해결한 알고리즘이라고 부르지 않는다. [PyTorch BCEWithLogitsLoss 공식 문서](https://docs.pytorch.org/docs/2.14/generated/torch.nn.BCEWithLogitsLoss.html)는 손실의 정의를 확인하는 근거이며, 이번 기술 실행 버전은 위에 적은 2.11이다.

반대로 미등록 항목을 전부 가리고 양성만 학습하면, 모든 장르를 높게 내는 퇴행적인 해를 막을 학습 신호가 부족하다. 이를 누락 태그 문제의 해결책으로 채택하지 않는다. 클래스 가중치나 정규화를 쓴다면 학습 분할에서만 계산하고, 작은 사전 고정 후보만 검증 분할로 고른다. 이 세부 학습 조건은 다음 실행 전 프로토콜에서 확정해야 한다.

## 무엇을 비교해야 하나

고정 P0의 텍스트 유사도 순위와 새 판별기의 관측 태그 검색을 같은 음원·구간에서 비교한다. 검증 분할에서 모델 선택을 마친 뒤 모델·조건을 고정하고, 기존에 보존한 33곡을 한 번만 최종 진단에 사용한다. 경계와 다른 장르 손실, 태그 동시 등록 사례를 모두 제시해야 한다.

이미 결과를 본 RWC 30곡·Jamendo 60곡은 진단 자료이며, 이번 학습이나 하이퍼파라미터 선택용으로 자동 편입하지 않는다. 다시 확인하더라도 독립 평가로 세지 않는다. 새 33곡도 매우 작고 업로더 태그가 불완전하므로, 통계적 우열·전문가 장르 정답률·현대 J-pop 정확도·배포 준비 완료를 이 자료만으로 확정할 수 없다.

## 확보 비용과 재사용 조건

후보 350곡은 메타데이터 길이 합으로 약 **1,343.6분(22.4시간)**이다. 현재 확보된 학습 음원은 0곡이며 접근 성공 여부는 미확인이다. 파일당 허용 응답을 28,000,000바이트로 제한할 경우 성공 페이로드 합의 상한은 **9.8GB**다. 이는 예상 실제 크기나 재시도·전송 부가량을 포함한 총 네트워크 상한이 아니다. 추가 다운로드는 이번 단계에서 수행하지 않았다.

후속 확보에는 고정 선정·게시 SHA256·디코딩·길이·유한 값·비무음·분할별 양성 커버리지 확인이 필요하다. 접근 실패를 모델 점수가 좋은 곡으로 바꾸거나, 계획하지 않은 미러를 즉석에서 쓰지 않는다. 아직 내려받을 수 없는 후보를 학습 완료 곡으로 세지 않는다.

MuQ 코드의 MIT와 모델 가중치 CC-BY-NC 4.0은 구분한다. Jamendo도 메타데이터 조건과 개별 오디오 조건을 분리해 확인해야 하며, 공식 안내는 비상업 연구·학술 이용을 설명한다. 따라서 현재 제안은 개인의 비상업 연구 경로이며, 분리한 판별기를 상업적으로 자유롭게 배포할 수 있다고 확정하지 않는다. ## 완료 범위와 다음 작업

완료한 것은 공식 자료 확인, 메타데이터 분리·선정·양성 커버리지 검사, 실제 음악 특징 추출과 합성 목표의 역전파 동작 점검이다. **장르 학습·새 음원 다운로드·성능 개선 검증은 아직 하지 않았다.** 사용자가 전문 라벨을 작성할 일은 없다.

다음 작업은 이 280/70 구성을 바탕으로 확보 예산·실패 처리·손실 함수·정규화 후보·검증 선택 기준을 고정한 뒤, 작은 판별기의 학습 파일럿을 준비하는 것이다. 그 단계에서도 최종 33곡은 모델 선택이 끝날 때까지 사용하지 않는다.

근거는 `data/evaluation/genre_supervision_feasibility_v1/assessment.json`, 기술 동작 기록은 `work/genre-supervision-feasibility/runtime-probe.json`에 있다. `scripts/assess_genre_supervision.py`로 고정 메타데이터와 선정 결과를 재확인할 수 있다. 기존 P1 실패 결과와 계획은 덮어쓰지 않았다.
