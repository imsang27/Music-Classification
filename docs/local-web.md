# 브라우저에서 음악 분류하기

현재 MuQ 모델은 Python과 모델 가중치가 필요합니다. GitHub Pages는 정적 파일만 제공하며 Python 서버를 실행하지 않으므로, 현재 프로그램을 github.io에서 단독 실행할 수 없습니다. [GitHub 공식 설명](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)

이 컴퓨터에서 서버를 열고 브라우저로 사용합니다. **첫 화면 `/`는 기존 웹페이지 디자인과 입력 구성을 유지합니다. 그곳의 ‘AI로 분석하기’를 누르면 별도 주소 `/ai`의 현재 분류 화면으로 이동합니다.** 파일·링크·일괄 입력의 세 AI 버튼 모두 파일 선택이나 필수 입력 검증 없이 이동합니다. 실제 AI 입력과 분석은 이동한 화면에서 시작합니다.

현재 페이지의 ‘기존 페이지로’ 또는 로고를 누르면 첫 화면으로 돌아갑니다. 기존 화면의 규칙 분류·링크 미리보기·업로드 관리는 공통 API를 사용하며, 직접 분류 버튼은 직접 선택 화면으로 연결합니다. 미구현 ML·통합·범위 밖 가사 기능은 실행하지 않습니다.

## 처음 설치할 때

프로젝트 폴더의 PowerShell에서 실행합니다. 기존 `.venv` 환경이 있으면 첫 번째 명령은 생략합니다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[desktop,web]"
.\.venv\Scripts\python.exe scripts/setup_tagging_model.py
```

이미 같은 프로젝트에서 모델을 설치했다면 모델 준비 명령을 다시 실행할 필요가 없습니다. 모델은 약 2.65GB이며 설치·사용 조건과 YouTube용 FFmpeg 설정은 [모델 설치 안내](desktop-tagging.md)를 따릅니다. 실행 프로그램은 모델을 자동으로 새로 학습하거나 변경하지 않습니다.

## 실행과 사용

화면 상단 **AI 분류**에 두 탭을 통합했습니다. 헤더와 탭은 스크롤해도 상단에 남습니다. 탭은 방향키·Home·End로도 이동할 수 있고 분류 중에는 전환이 잠깁니다. 방식별 결과와 다운로드는 구분해 유지합니다.

환경 확인·분류 중에는 결과 영역에 스켈레톤이 표시됩니다. 완료·입력 오류·다운로드 요청은 토스트로 안내하며, 오류 내용은 결과 영역에도 남습니다. 토스트는 닫기 버튼으로 닫을 수 있고 마우스를 올리거나 키보드 초점이 있으면 자동 닫힘이 일시 정지됩니다. 모델 탭·도움말의 `?`·다운로드 항목은 마우스 또는 키보드 초점으로 툴팁을 확인할 수 있습니다. 툴팁은 Escape로 닫습니다. 탭·결과 전환과 버튼 반응에는 짧은 효과를 적용하며 운영체제의 움직임 줄이기 설정을 따릅니다.

| 탭 | 실제 분류 | 분석 범위 |
|---|---|---|
| 현재 방식 · MuQ | 장르25·감정9·분위기11 | 입력 전체를 구간으로 종합 |
| 기존 방식 · Wav2Vec2 | 기존10장르 | 앞부분 최대30초, 감정·분위기 미지원 |

두 방식 모두 파일·여러 파일·YouTube 영상 한 곡을 같은 화면에서 처리합니다. YouTube 오디오는 전체 영상 길이로 준비하지만 Wav2Vec2가 분류에 사용하는 범위는 앞부분30초입니다. 같은 곡이라도 출력 범위·분석 구간이 달라 두 결과가 같을 필요는 없습니다.

기존 `python main.py`, `python webapp/app.py` 실행도 동일한 통합 화면을 엽니다(기본 포트5000). `로컬_웹_실행.cmd`는8765를 사용합니다. 최초 웹 구현과 화면은 `webapp/legacy_app.py`, `webapp/templates/legacy_index.html`에 보존했습니다.

## 기존 페이지 기능의 통합 범위

| 메뉴·기능 | 현재 동작 |
|---|---|
| AI 분류 | MuQ·Wav2Vec2 선택, 기존 모델 상태·새로고침 |
| 규칙 분류 | 기존 템포 구간 규칙으로 장르·감정 참고 출력. 분위기는 미지원 |
| 직접 분류 | 브라우저에서 곡 이름·장르1개·감정/분위기 각1~3개 선택 후 저장. 모델·음원·학습 불필요 |
| 입력 방식 | 파일·여러 파일·YouTube·HTTPS 음원·여러 링크 순차 처리 |
| 미리보기 | YouTube 제목·채널·길이 조회. 직접 음원은 파일 이름·주소 형식 확인 |
| 업로드 관리 | 기존 보관 파일 목록·크기 확인, 복구 가능한 보관함 이동과 최근 정리 복구 |
| 밝기 | 다크/라이트 모드 전환과 브라우저 설정 저장 |
| 기타 기능 | 미구현 ML·통합 분류를 명시하고 가사 분석은 현재 범위에서 제외 |

규칙 분류는 기존의 템포<80/110/140에 따른 장르와 <80/100/120에 따른 감정 조건을 유지합니다. 처음60초에서 템포를 구하고 고정 숫자를 신뢰도처럼 표시하지 않습니다. 손상·무음·너무 짧은 입력에는 기본 태그를 채우지 않습니다. 기존 규칙의 ‘행복한·슬픈’ 등 표현은 이 참고 기능에만 남으며 MuQ의 승인된 키워드 목록을 바꾸지 않습니다.

여러 링크는 한 번에 최대10개이며 같은 선택 방식으로 순차 처리합니다. 각 임시 오디오는 다음 링크 처리 전에 삭제하고, 실패한 항목도 순서를 유지해 기록합니다. HTTPS 직접 음원은 WAV·MP3·FLAC·OGG·M4A·AAC, 최대100MiB를 지원합니다. 공개 주소·리다이렉트·TLS를 확인하며 사설 IP와 로그인 URL을 받지 않습니다. 제목·채널은 표시용입니다.

업로드 관리 기본 대상은 프로젝트의 `uploads/`입니다. 다른 기존 프로젝트의 폴더를 연결하려면 무시되는 개인 파일 `config/web_paths.local.json`에 `{"uploads_directory":"C:/path/to/uploads"}`를 지정하거나 `MUSIC_CLASSIFICATION_UPLOADS`를 사용합니다. 새 분석 복사본은 계속 자동 삭제되므로 기존 보관 파일이 없으면 목록은0개입니다. 관리 화면은 음원 파일만 대상으로 하며 노트·하위 폴더·링크 파일을 정리하지 않습니다. 정리한 파일은 `work/upload-trash/`에 보관해 되돌릴 수 있고 같은 이름의 새 파일을 덮어쓰지 않습니다. 이 보관함은 운영체제 휴지통과 별개입니다.

기존 모델은 자동 다운로드하지 않습니다. 이미 보유한 체크포인트 폴더를 개인 설정의 `genre`에 추가합니다. 상대 경로는 설정 JSON을 기준으로 합니다. 모델 추론은 설정된 MuQ용 Python 환경을 재사용하며 MuQ가 없으면 서버 Python을 사용합니다. 이 환경에 `genre` 추가 의존성이 필요합니다.

```json
"genre": {
  "checkpoint": "../models/my-wav2vec2-snapshot",
  "device": "cpu"
}
```

1. **로컬_웹_실행.cmd**를 더블클릭합니다.
2. 브라우저가 자동으로 열립니다. 열리지 않으면 **http://127.0.0.1:8765**에 접속합니다. 기존 페이지가 첫 화면입니다.
3. **AI로 분석하기**를 눌러 **http://127.0.0.1:8765/ai**로 이동한 뒤 음원이나 링크를 입력하고 **분류 시작**을 누릅니다.
4. 장르 대표값과 감정·분위기 각각 최대 3개 후보를 확인합니다.
5. **Markdown 저장**, **태그 JSON 저장**, **상세 결과 저장**으로 원하는 결과를 내려받습니다.

서버 창을 열어 둔 동안 사용할 수 있습니다. 종료하려면 해당 창에서 **Ctrl+C**를 누릅니다. 진행 중인 분석이 있으면 정리를 마친 후 종료됩니다. 브라우저 탭을 닫아도 시작한 분석은 계속됩니다. 같은 서버 실행 중에는 새로고침하면 진행 중이거나 이 탭에서 마지막으로 확인한 작업을 다시 볼 수 있습니다. 서버 재시작 후에는 새 작업을 시작하며, 이전 결과는 디스크에 남아 있습니다.

파일 입력은 WAV·MP3·FLAC·OGG·M4A·AAC를 지원하며 최대 20개, 파일당 100MiB, 합계 500MiB입니다. 파일 복사본을 임시로 분석한 뒤 삭제합니다. 같은 이름의 파일도 서로 덮어쓰지 않습니다. 원본 음원과 Obsidian 노트는 수정하지 않습니다.

YouTube 입력은 로그인 없이 열리는 20분 이하 영상 한 곡입니다. 재생목록 전체는 지원하지 않습니다. 분석용 다운로드는 분류 후 삭제하며 영상 제목·채널 정보는 분류 근거로 사용하지 않습니다. 접근 제한이나 네트워크 상태로 링크 입력이 실패할 수 있습니다.

분석은 한 작업씩 실행합니다. 첫 실행과 여러 곡 분석에는 시간이 걸릴 수 있으며, 화면은 작업 상태를 표시합니다. 실제 진행률을 계산한 백분율은 표시하지 않습니다. 실패한 파일은 실패로 남기고 임의의 태그를 만들지 않습니다.

결과는 프로젝트의 `outputs/local-web/<작업ID>/`에 자동 저장됩니다. 업로드 오디오는 결과 폴더에 보관하지 않습니다. JSON의 대표값과 대안 후보, 원시 점수의 의미는 [분석·평가 안내](research/README.md)를 참고하세요.

## 다른 포트 또는 기존 모델 설정 사용

YouTube 연결 도구가 없다는 메시지가 보이면 **서버를 실행하는 Python 환경**에 다음 명령을 실행하고 화면을 새로고침합니다. 모델용 별도 Python 환경에만 설치하면 웹 서버에서 사용할 수 없습니다. `web` 설치 옵션에는 yt-dlp와 soundfile도 포함됩니다. FFmpeg는 별도로 준비해야 합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[web]"
```

```powershell
.\.venv\Scripts\python.exe local_tagging_server.py --port 8766
.\.venv\Scripts\python.exe local_tagging_server.py --settings "C:\path\model_paths.local.json"
```

기존 다른 폴더의 모델을 재사용하려면 `config/model_paths.local.json`에 MuQ 설치·Python·캐시 경로를 설정하거나 `--settings`로 설정 파일을 지정합니다. `MUSIC_CLASSIFICATION_SETTINGS`도 지원합니다. 경로는 개인 설정이며 GitHub에 올리지 않습니다. 화면의 준비 상태는 설정·실행 파일·런타임 기록의 존재 확인이고, 가중치 검증과 실제 모델 적재는 분류 실행 시 진행합니다.

서버는 `127.0.0.1`에만 열립니다. 외부 컴퓨터·휴대전화·github.io 화면에서 이 서버를 호출하는 구성은 포함하지 않습니다. HTML·CSS·JavaScript도 로컬에서 제공하며 외부 UI 서비스나 CDN에 의존하지 않습니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[desktop-test]"
.\.venv\Scripts\python.exe scripts/test_desktop.py
```

웹 검사에는 업로드·복수 파일·중복 이름·실패·용량 제한·임시 파일 정리·동시 요청·링크 전달·결과 다운로드와 다른 출처 요청 차단을 포함합니다. 자동 검사에서는 모델·YouTube 접근을 대체하고 실제 분류 품질을 채점하지 않습니다.
